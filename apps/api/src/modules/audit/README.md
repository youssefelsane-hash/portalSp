# modules/audit

سجل التدقيق (Audit Logs) — تسجيل كل عملية إدارية حساسة: مين عملها، إمتى، من أي IP وجهاز، وقبل/بعد التعديل. جدول: `audit_logs` (قاموس §11.1، من `infra/migrations/0011`).

**الحالة: شغال.**

- **موديول خفيف مستقل عمداً** (مش جوّه `admin`) — عشان أي موديول تاني (`orders`, `technicians`, `payments`, `support`, `promotions`) يسجّل تدقيق من غير ما يعتمد على موديول `admin` نفسه (اللي بيعتمد هو على كيانات الموديولات دي أصلاً)، ومنعاً لأي اعتمادية دائرية بين الموديولات.
- **`AuditLogService.record()`**: مبيرميش استثناء أبداً — لو كتابة السجل فشلت، بتتسجّل في اللوج بس ومتوقفش العملية الإدارية الحقيقية (صرف اتوافق عليه، طلب اتلغى) اللي استدعتها. نفس فلسفة `NotificationsService.notify()`.
- **`AuditContext` decorator** (`common/decorators/audit-meta.decorator.ts`): بيلمّ `ip`/`user-agent`/`request_id` من الـ request في نداء واحد، بيتحط كباراميتر أخير اختياري في أي controller method بيسجّل تدقيق.
- **موصول فعلياً بـ 10 أفعال إدارية حساسة** عبر 5 موديولات: اعتماد/رفض فني ومراجعة مستنداته (`technicians`)، إلغاء/تعيين طلب يدوي (`orders`)، موافقة/رفض/إتمام صرف وإصدار استرجاع (`payments`)، حل/رفض/قفل شكوى (`support`)، إنشاء/تعطيل كود خصم ونقاط ولاء يدوية (`promotions`)، ومنح/سحب دور إداري (`admin` — أهم عملية في النظام كله، لازم تتسجّل).
- **`GET /admin/audit-logs`**: فلترة بـ `entity_type`, `entity_id`, `actor_user_id`, `action`, وفترة زمنية + صفحات. **مقصورة على `super_admin` بس** عبر صلاحية `audit.view` الجديدة (`infra/migrations/0021_audit_view_permission.sql`) — مطابق حرفياً لطلب "Super Admin يشاهد Audit Logs كاملة"، مش أي أدمن.
- اتعمله اختبار end-to-end فعلي: أدمن (`super_admin`) اعتمد فني بـ `User-Agent` مخصص → السجل ظهر بكل التفاصيل (`actor_ip`, `user_agent` في القاعدة مباشرة، `old_values`/`new_values`, `request_id`)، `ops_manager` (مالوش `audit.view`) اترفض من مشاهدة السجل، منح وسحب دور إداري الاتنين اتسجلوا بالتفاصيل الصح، فلترة بفعل معيّن أو فعل مش موجود رجّعت النتيجة الصح.
- **فجوة موثّقة**: مش كل عملية في النظام بتتسجّل — بس الأفعال الإدارية الحساسة المذكورة فوق. عمليات العميل/الفني العادية (إنشاء طلب، قبول طلب) عندها بالفعل `order_status_history` كسجل تاريخي خاص بيها، فمش محتاجة تتكرر هنا.
