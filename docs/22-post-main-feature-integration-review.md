# مراجعة تكامل الميزات المضافة إلى main — 2026-08-24

المراجعة شملت دفعات `10e18bb` إلى `6be3dc7`: الحجز المتكرر، المشاريع،
الضمان، التقسيط، وإعداد Paymob. الغرض ليس مراجعة الشاشات فقط، بل إثبات
الربط من العميل إلى API ثم PostgreSQL ولوحة الإدارة.

## قرارات التكامل

- الطلب الأول الذي ينشئ خطة تكرار يبقى `order_type=standard` للتوافق، لكنه يُربط بـ
  `recurring_template_id` و`recurring_occurrence_at` في نفس المعاملة. لذلك يظهر في قائمة
  الطلبات الكلية وكحجز متكرر، وتظل شاشة الحجوزات المتكررة مخصصة لإدارة الخطط.
- أي `milestone_id` في طلب يجب أن ينتمي لـ`project_id` نفسه ولنفس العميل. قراءة
  المشروع والعروض مقيدة بالملكية، وإنشاء العرض وإرساله والمراحل معاملات ذرية
  بتدقيق إجباري. لا يمكن نقل المشروع يدوياً إلى انتظار موافقة العميل من دون إرسال
  عرض فعلي، ولا يمكن للإدارة تسجيل قبول العميل. قائمة الإدارة متصفحة من المصدر،
  وتحفظ أوصاف بنود عرض السعر كما أدخلت.
- إكمال طلب مدفوع ذي مدة ضمان ينشئ `customer_warranties` في نفس المعاملة المالية.
  المدة بالأيام تُحفظ بالضبط، والضمان يرتبط بالطلب وبالمشروع إن وُجد. لا يمكن
  فتح أكثر من مطالبة نشطة أو تجاوز `max_claims` حتى مع طلبين متزامنين.
- دورة مطالبة الضمان مقيدة بالحالات المسموحة. كل قرار إداري يحتاج
  `warranty.review` ويُكتب مع سجل التدقيق في نفس المعاملة.
- خطط التقسيط النشطة تظهر للعميل مع `allowed_provider`. إذا استهدفت سياسة التقسيط
  فئة كاملة وأرسلت الواجهة `service_id` فقط، يستنتج API الفئة من الخدمة. الواجهات ترسل
  معرفات نسخ السياسات المطلوبة ووسيلة دفع متوافقة. إنشاء/تعديل الخطط والسياسات
  وربطها بالخدمات عمليات ذرية مع التدقيق.
- إعداد Paymob المفضل من لوحة الإدارة. الأسرار مشفرة في قاعدة البيانات ومخفية
  في الردود وسجل التدقيق. لا يصبح المزود جاهزًا إلا بوجود API Key وSecret Key وPublic Key
  وCard Integration ID وHMAC Secret.

## إثبات الانحدار

الاختبارات الحية تغطي ذرية إنشاء أول طلب متكرر، ملكية المشروع، إنشاء
ضمان موحد بالمدة الدقيقة، سباق آخر مطالبة، سياسة تقسيط مستهدفة بالفئة، تسلسل
نشر السياسات مع التزامن، وتحميل Paymob من إعداد مشفر دون إعادة تشغيل.

شغّل التحقق النهائي `159` مجموعة Jest و`887` اختباراً على PostgreSQL الحقيقي مع
`--detectOpenHandles`، وانتهت العملية تلقائياً من دون اتصالات Redis أو PostgreSQL
معلقة. كما طابقت جميع migrations حتى `0181` checksums المسجلة ونجحت invariants
المالية بعد إزالة فحص بنية العمالة المنزلية القديمة التي ألغتها migration `0169`.
