# دليل التعافي من الكوارث (Disaster Recovery)

> **اقرأ ده وإنت مرتاح، مش وإنت في نص الحادثة.** الخطوات هنا اتنفّذت واتقاست فعلاً
> (`node scripts/backup-restore-audit.js` — ١٤/١٤)، مش مكتوبة من الذاكرة.

## الأرقام المقاسة

| المقياس | القيمة | إزاي اتقاست |
|---|---|---|
| زمن أخد النسخة | **٠.٦ ثانية** لقاعدة ٤٨MB | `scripts/backup-db.sh` في تدقيق ج-١٠ |
| زمن الاسترجاع (RTO) | **٤.٧ ثانية** لنفس الحجم | `scripts/restore-db.sh` في نفس التدقيق |
| فقد البيانات الأقصى (RPO) | **٢٤ ساعة** | الجدولة يومية (`baytak-backup.timer`) |

**الأرقام دي بتكبر مع القاعدة.** أعد قياسها كل كام شهور بنفس السكريبت — RTO لقاعدة ٥٠GB
مش هيبقى ٥ ثواني، ولازم الرقم الحقيقي يكون معروف **قبل** الحادثة. لو الـRPO (٢٤ ساعة) بقى
غير مقبول تجاريًا، الحل هو WAL archiving / PITR — قرار تشغيلي للمالك، مش تغيير في السكريبتات.

## الروتين اليومي (بيشتغل لوحده)

`infra/systemd/baytak-backup.timer` بيشغّل `scripts/backup-db.sh` الساعة ١:٠٠ UTC (٣ الفجر
بتوقيت القاهرة). كل نسخة:
1. `pg_dump --format=custom` مضغوطة.
2. **بتتحقق فورًا**: `pg_restore --list` بيقرا فهرس الأرشيف، وبيتأكد إن الجداول الجوهرية
   (`orders`, `users`, `payments`, `wallet_transactions`, `technician_profiles`) فيها بيانات.
3. بتكتب `manifest.json` فيه الحجم وبصمة `sha256` وعدد الجداول.
4. الاحتفاظ ١٤ يوم — **والحذف بيحصل بعد نجاح النسخة الجديدة**، فنسخة فاشلة مابتمسحش آخر
   نسخة سليمة.

أي فشل بيخرج بكود ≠ 0 فالوحدة بتفشل في `systemd`. **اربط الفشل ده بمراقبتك** — نسخة بتفشل
بصمت أخطر من مفيش نسخة خالص، لأن الاتنين بيدّوا نفس النتيجة وقت الكارثة بس الأولى بتدّي
طمأنينة كاذبة لحد ساعتها.

## اختبار الاسترجاع الدوري (إلزامي — شهريًا)

```bash
node scripts/backup-restore-audit.js
```

بيزرع بيانات معروفة، ياخد نسخة، **يمسح البيانات فعلاً**، يرجّع في قاعدة منفصلة، ويقارن صف
بصف (بما فيها الجداول المرتبطة والفهارس وقيود المفاتيح الأجنبية). ١٤/١٤ = النسخ تقدر ترجع.

## وقت الحادثة

### ١. اهدى وحدّد النوع
- **فقد بيانات جزئي** (حذف بالغلط، migration وحش): استرجاع في قاعدة منفصلة ⟵ انسخ الناقص بس.
- **فقد كامل** (القرص/السيرفر راح): استرجاع كامل على سيرفر جديد.

### ٢. وقّف الكتابة قبل أي حاجة
```bash
sudo systemctl stop baytak-api
```
استرجاع فوق قاعدة والتطبيق بيكتب فيها بيخلط بيانات قديمة بجديدة — وده أصعب في الإصلاح من
الفقد الأصلي.

### ٣. اختار النسخة وتأكد منها
```bash
ls -lt /var/backups/baytak/*.dump | head
cat /var/backups/baytak/baytak-<الوقت>.dump.manifest.json
sha256sum /var/backups/baytak/baytak-<الوقت>.dump    # لازم يطابق اللي في الـmanifest
```
عدم التطابق = الملف اتلف على القرص. **روح للنسخة اللي قبلها** ولا تحاول تصلّحه.

### ٤. ارجّع — في قاعدة منفصلة الأول
```bash
scripts/restore-db.sh /var/backups/baytak/baytak-<الوقت>.dump
```
من غير `--target`، الاسترجاع بيروح لقاعدة جديدة `baytak_restore_<وقت>` **ومابيلمسش الشغّالة**.
ده مقصود: افحص الأول، وبعدين قرر.

```bash
psql "postgres://baytak@localhost:5432/baytak_restore_<وقت>" \
  -c "SELECT count(*) FROM orders; SELECT max(created_at) FROM orders;"
```
`max(created_at)` بيقولك آخر لحظة موجودة في النسخة — يعني بالظبط قد إيه اتفقد.

### ٥. القرار
- **جزئي**: انسخ الصفوف الناقصة من القاعدة المسترجَعة للشغّالة (`INSERT … SELECT` عبر
  `postgres_fdw` أو `pg_dump -t جدول --data-only`). أضمن من استرجاع كامل بيرمي شغل صحيح.
- **كامل**: 
  ```bash
  scripts/restore-db.sh <ملف.dump> --target baytak --force
  ```
  `--force` مطلوب صراحةً — عشان الأمر ما يتنفّذش من الذاكرة تحت الضغط.

### ٦. طبّق الـmigrations اللي بعد النسخة
```bash
node infra/migrations/migrate.js
node scripts/check-migrations.js
```
النسخة بتحتوي schema لحظة أخدها. لو اتعمل deploy فيه migrations بعدها، لازم تتطبّق تاني.

### ٧. شغّل وتأكد
```bash
sudo systemctl start baytak-api
curl -s localhost:3000/api/v1/health
# ثوابت الفلوس — أهم فحص بعد أي استرجاع
node scripts/financial-idempotency-audit.js
```

### ٨. بلّغ
الطلبات اللي اتعملت بين آخر نسخة ولحظة الحادثة **اتفقدت فعلاً**. حدّدهم من
`max(created_at)`، وبلّغ العملاء والفنيين المتأثرين. الصمت هنا بيتحوّل لأزمة ثقة أكبر من
العطل نفسه.

## اللي **مش** مغطّى بصراحة

- **الملفات المرفوعة (S3/القرص) مش في النسخة دي** — `pg_dump` بيرجّع القاعدة بس. صور الطلبات
  ومستندات الفنيين محتاجة نسخ منفصلة (versioning على البكت لو S3). ده **فجوة مفتوحة**.
- **مفيش نسخ خارج السيرفر** — النسخ على نفس الجهاز، فضياع الجهاز = ضياع النسخ معاه. الخطوة
  الجاية الإلزامية قبل الإطلاق: مزامنة `/var/backups/baytak` لتخزين خارجي.
- **مفيش PITR** — الاسترجاع لحظة النسخة فقط، مش لأي ثانية.
