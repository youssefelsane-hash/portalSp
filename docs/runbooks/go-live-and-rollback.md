## ٠. القاعدة الحاكمة: **الرجوع غير متماثل**

أخطر افتراض ممكن تدخل بيه يوم الإطلاق هو إن «لو حصل حاجة هنرجّع النسخة القديمة». في النظام ده
**ده مش صحيح تلقائيًا**، ومش سهو — دي نتيجة قرارات معمارية مقصودة وموثّقة:

| الحاجة | بترجع؟ |
|---|---|
| كود الـAPI | ✅ نشر النسخة السابقة — **بشرط** أنها تشتغل على السكيما الجديدة |
| سكيما القاعدة | ❌ **مفيش migrations عكسية** (`down`) بقرار موثّق — الإصلاح تقدّمي دايمًا |
| فلوس اتحركت | ❌ استرداد، مش rollback |
| إشعارات اتبعتت | ❌ وصلت خلاص |
| webhooks اترد عليها `200` | ❌ البوابة الخارجية اعتبرتها مستلمة |
| تطبيق منشور على Google Play | ⚠️ بطيء (مراجعة) — والمستخدم ممكن يكون محدّث خلاص |

**النتيجة العملية:** الرافعة الأولى وقت الحادثة **مش** الرجوع للنسخة القديمة. هي **مفاتيح
الإيقاف** (ج-١٧/ج-١٨): بتسري في ثواني، وقابلة للعكس بالكامل، ومابتلمسش الشغل الجاري.

## ١. قبل الإطلاق — البوابة الميكانيكية

```bash
node scripts/go-live-preflight.js
```

بترجع `0` لو كل الشروط متحققة. **لو رجعت `1` مايتطلقش** — كل شرط فيها لو ناقص بيخلّي الرجوع
مستحيل أو بخسارة بيانات:

| الشرط | ليه هو بوابة |
|---|---|
| مفيش رقم migration مكرر | حصل فعلاً بين سيشنين متوازيين — واحد بيتسجّل والتاني يتجاهَل بصمت ⇒ سكيما ناقصة |
| كل الهجرات آمنة (`check-migration-safety`) | `ALTER TABLE` بلا `lock_timeout` بيجمّد كل استعلامات الجدول |
| كل الهجرات متطبّقة | كود جديد + سكيما قديمة = أعطال فورية |
| **مفاتيح الإيقاف موجودة ومفتوحة** | من غيرها أول حادثة = نشر كود تحت ضغط. وقد اتمسحت فعلاً مرة بلا إنذار (اتصلح في `0306`) |
| عتبات الإنذار مسجّلة | `PATCH` بيرمي `404` لمفتاح مش موجود ⇒ المراقبة مش قابلة للضبط وقت الحادثة |
| **نسخة احتياطية < ٢٤ ساعة** | الشرط الوحيد اللي مالوش بديل — كل رافعات الرجوع بتفشل لو البيانات اتخربت |
| الدفتر متوازن + مفيش رصيد سالب | خلل مالي موجود دلوقتي هيتضاعف على حجم حقيقي |
| متغيّرات البيئة (ج-١٤) | `NODE_ENV` غير إنتاجي بيتخطّى **كل** حُرّاس fail-fast |

> البوابة مصمّمة تتشغّل **على الهدف اللي هيطلع**. تشغيلها على جهاز تطوير بيفشّل `ب-٤` و`ب-٦`
> **صح** (مفيش نسخ احتياطية، و`.env` تطويري) — والسكريبت بيقول كده صراحةً.

### فحوصات الجودة (نفس بوابة CI)

```bash
cd apps/api && npx tsc --noEmit && npx eslint src --max-warnings 0 && npx nest build && npx jest -w=1
```

## ٢. ترتيب الإطلاق

الترتيب **مش تفصيلة** — كل خطوة بتفترض اللي قبلها خلص.

1. **نسخة احتياطية فورية** — `scripts/backup-db.sh` (حتى لو الليلية اشتغلت). دي نقطة الرجوع
   الوحيدة لو حصل الأسوأ. تحقق إن الملف اتكتب فعلاً، مش إن الأمر رجع `0`.
2. **الهجرات** — `node infra/migrations/migrate.js`. بيشتغل بـ`lock_timeout` و`statement_timeout`
   (راجع `docs/runbooks/migrations.md`). لو وقف بـ`55P03`/`57014`: **ده مش غلط في الـSQL —
   الحماية اشتغلت**، فيه transaction مفتوحة على الجدول. دوّر عليها وأقفلها، وأعد التشغيل.
3. **نشر الـAPI** — بعد ما السكيما بقت جاهزة.
4. **التحقق** (قسم ٣) — **قبل** ما تفتح الأبواب.
5. **الويب والتطبيقات** — آخر حاجة. التطبيقات المنشورة مالهاش رجوع سريع، فما تنشرهاش قبل ما
   الباك-إند يثبت.

### فتح الأبواب على مراحل

لو الحجز مقفول أثناء النشر (وده الوضع الأأمن)، افتحه بالترتيب ده من
`PATCH /admin/settings/:key`:

1. `orders.new_bookings_enabled = true` — الحجز العادي.
2. راقب ١٥–٣٠ دقيقة على `/admin/ops/health-metrics`.
3. `orders.emergency_bookings_enabled = true` — الطوارئ آخر حاجة: أعلى مخاطرة (بتتجاهل
   الجدول، بتوصل لفنيين مشغولين، سعرها أعلى).

## ٤. متى نتدخّل — عتبات مش إحساس

من `/admin/ops/health-metrics` (العتبات نفسها قابلة للضبط بلا نشر — ج-١٨):

| الإشارة | العتبة | التصرّف |
|---|---|---|
| نسبة أعطال 5xx | ≥ ٢٠٪ | **إيقاف الحجز فورًا** ثم شخّص |
| نسبة أعطال 5xx | ≥ ٥٪ | راقب عن قرب، جهّز الإيقاف |
| زمن الاستجابة p95 | ≥ ١٠ ثوانٍ | إيقاف الحجز — بطيء أوقع من مقفول |
| طلبات مستنية اتصال قاعدة | مستمرة > 0 | ضغط حقيقي — قلّل الحمل |
| عمليات دفع فاشلة/ساعة | ≥ ١٠ | **اقفل وسيلة الدفع المتأثرة وحدها** |
| طلبات عالقة `searching_technician` | > ٣٠ دقيقة | مشكلة توزيع مش مشكلة حجز |

**قاعدة المالك الحاكمة:** «ضعيف بطيء ماشي، بس ما يقعش». إيقاف الحجز مؤقتًا **قرار سليم**، مش
اعتراف بالفشل — الطلبات القائمة وتنفيذها ودفعها بتفضل شغّالة (اتقاس في ج-١٧).

## ٥. شجرة الرجوع

### المستوى ١ — مفاتيح الإيقاف (ثواني، قابل للعكس) ← **ابدأ من هنا دايمًا**

```
PATCH /admin/settings/orders.new_bookings_enabled        false   # الحجز كله
PATCH /admin/settings/orders.emergency_bookings_enabled  false   # الطوارئ وحدها
PATCH /admin/settings/payments.<method>_enabled          false   # وسيلة دفع بعينها
```

يحتاج `settings.manage` + توكن step-up. بيسري **فورًا** بلا إعادة تشغيل.
**الكتابة المباشرة بـSQL مش كافية** — بتعدّي على الكاش فالقيمة القديمة بتفضل شغّالة.

الشغل الجاري **مابيتأثرش**: الفني بيكمّل ويقفل، والعميل بيدفع لشغل خلص، والإلغاء شغّال.

### المستوى ٢ — رجوع الكود (دقايق)

انشر النسخة السابقة. **قبل ما تعمل كده اسأل سؤال واحد:**

> هل النسخة القديمة تقدر تشتغل على السكيما الحالية؟

- **عمود اتضاف** (nullable أو بـdefault) ⇒ آمن، الكود القديم بيتجاهله.
- **عمود اتشال، أو اتغيّر نوعه، أو قيد جديد بيرفض بيانات الكود القديم** ⇒ **الرجوع هيكسر**.
  في الحالة دي الطريق الوحيد هو **الإصلاح التقدّمي**: hotfix للأمام، مش رجوع.

لو الرجوع آمن: انشر القديم، وسيب السكيما زي ما هي. **ما تحاولش تعكس هجرة بإيدك تحت الضغط** —
دي أسرع طريقة لخسارة بيانات.

### المستوى ٣ — استرجاع القاعدة (آخر حل، **بخسارة بيانات**)

`scripts/restore-db.sh` — اتقاس فعليًا في ج-١٠ باسترجاع كامل ومقارنة صف-بصف.

**ثمنه صريح:** كل حاجة حصلت بعد وقت النسخة بتضيع — طلبات، مدفوعات، تقييمات. يعني عملاء دفعوا
فعلاً ومفيش أثر لدفعهم. **مايتعملش إلا لو البيانات نفسها اتخربت** (خلل منطقي كتب صفوف غلط على
نطاق واسع)، ومع خطة تواصل مع العملاء المتأثرين.

قبل الاسترجاع: **خد نسخة من الحالة الحالية المخربة** — هتحتاجها للتحقيق وللتوفيق اليدوي.

## ٦. اللي **مايترجعش** أبدًا

خطة رجوع بتتجاهل الحاجات دي بتدّي ثقة كاذبة:

- **فلوس اتحركت** — المعالجة استرداد (`refunds`)، والدفتر لازم يفضل متوازن. `rollback` مش
  بيرجّع فلوس لحد.
- **إشعارات اتبعتت** — SMS/push وصلوا. لو الإشعار كان غلط، الإصلاح **إشعار تصحيح**، مش صمت.
- **webhooks اترد عليها `200`** — البوابة اعتبرتها نهائية ومش هتعيدها.
- **نسخة منشورة على المتاجر** — الرجوع مراجعة تانية (ساعات لأيام)، وناس كتير هتفضل على النسخة
  الجديدة. فالمفاتيح في الباك-إند هي وسيلة السيطرة الحقيقية على تطبيق منشور.

## ٧. بعد الحادثة

1. **ارفع المفاتيح بالتدريج** — عادي الأول، طوارئ بعد ما تستقر.
2. **تحقق من الثوابت المالية**: الدفتر متوازن + مفيش رصيد سالب
   (`node scripts/go-live-preflight.js` بيغطّي الاتنين).
3. **`node scripts/find-error.js --last 20`** — من كود الخطأ للسبب الحقيقي.
4. **اكتب اللي حصل** — سبب جذري، ومقياس كان هيكشفه أبدر، وبوابة تمنع تكراره. لو الحادثة كشفت
   مقبض مش موجود، ضيفه كإعداد **دلوقتي** مش وقت الحادثة الجاية.
