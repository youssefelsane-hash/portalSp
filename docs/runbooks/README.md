# Runbooks — خطوات التعامل مع الأعطال

مرجع: `01-master-plan.md` §8 (الاستقرار / SRE).

**القاعدة:** كل runbook لازم يتكتب *قبل* الحادثة مش بعده، ويتراجع كل 3 شهور.

## القائمة الإلزامية (من اليوم الأول)

| الملف | الحادثة | الحالة |
|---|---|---|
| `db-outage.md` | انقطاع قاعدة البيانات | ⬜ لسه هيتكتب |
| `payment-gateway-down.md` | تعطل بوابة الدفع (Paymob/Fawry) | ⬜ لسه هيتكتب |
| `ddos-attack.md` | هجوم DDoS | ⬜ لسه هيتكتب |
| `data-breach.md` | تسرب بيانات | ⬜ لسه هيتكتب |
| `deploy-failure.md` | فشل نشر / rollback | ⬜ لسه هيتكتب |
| `earnings-v2-cutover.md` | تفعيل/إيقاف محرك المستحقات V2 ومطابقة الأموال | ✅ جاهز |

## شكل كل runbook (ثابت)

```
1. الأعراض  — إزاي تعرف إن الحادثة دي حصلت (alert / متابعة)
2. الأثر    — مين المتأثر (عملاء / فنيين / كله)
3. الاستجابة الفورية — أول 3 خطوات في أول 5 دقايق
4. التصعيد  — مين يتصل بيه ومتى
5. الإصلاح  — خطوات الحل الكامل
6. ما بعد الحادثة — post-mortem خلال 48 ساعة
```

كل runbook لازم يتربط بمعيار RTO < 1 ساعة و RPO < 5 دقايق (§8 في الماستر بلان).
