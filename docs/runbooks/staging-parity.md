# تطابق staging مع الإنتاج (ج-١٤)

> **القيمة الوحيدة لـstaging إنها تكشف الأعطال قبل العملاء.** staging مختلفة عن الإنتاج في
> حاجة جوهرية بتدّي العكس بالظبط: **ثقة كاذبة**. الملف ده بيحدّد اللي لازم يتطابق واللي لازم
> يختلف — والفرق بينهم مش تفصيلة.

## الأداة

```bash
node scripts/env-parity-check.js --env <ملف .env> --as staging
```

بيرجع `1` لو فيه فرق خطير. **شغّله قبل أي نشر على staging أو الإنتاج.**

الفاحص **مابيشوفش قيم الإنتاج** عمدًا — بيقارن الملف بمتطلبات البيئة المستهدفة، مش بملف تاني.
سكريبت بيقرا أسرار الإنتاج عشان يقارن بيها بيبقى هو نفسه خطر أمني.

القالب الجاهز: `infra/env/staging.env.template`.

## مصفوفة التطابق

### ١) لازم يتطابق — **شكل النظام**

تغيير أي واحدة فيهم بيخلّي staging بتختبر **نظامًا تاني**، فنتايجها بلا معنى.

| المفتاح | ليه |
|---|---|
| `STORAGE_PROVIDER` | **أخطر فرق ممكن.** محلي مقابل `s3` بيغيّر شكل الروابط والصلاحيات بالكامل. اتلقط حيًا في ج-١٣: رابط `/uploads/...` صحيح مع المحلي و`404` مع s3 |
| `NODE_ENV` (production-like) | كل حُرّاس fail-fast بتتخطّى في `development`. staging على `development` معناها إن الإقلاع اللي هيفشل في الإنتاج بينجح هنا |
| `DATABASE_POOL_MAX` وأخواتها | pool أوسع مش هيكشف أبدًا رفض `503` تحت التزامن — وده كان **P0-1 حقيقي** في هذا المشروع |
| `THROTTLE_LIMIT` | مرفوع = نظام بلا حدود. تدقيق ج-٩ بيقف صراحةً لو لقاه مرفوعًا |
| وجود Redis | **staging بلا Redis بتخفي كل بَقّات الطوابير** — المسار الاحتياطي بيشتغل دايمًا فالبَقّة اللي بتظهر تحت الطابور مابتظهرش خالص |
| إصدار Postgres + الامتدادات (PostGIS) | استعلام جغرافي بيشتغل على إصدار ويفشل على تاني. `postgis/postgis:16-3.4` في `infra/docker/docker-compose.yml` هو المرجع |

### ٢) لازم يختلف — **العزل**

تطابقها معناه إن تدقيق على staging بيلمس **بيانات وفلوس عملاء حقيقيين**.

| المفتاح | لو اتشارك |
|---|---|
| `DATABASE_URL` | تدقيق بيمسح بيانات عملاء حقيقية (كل سكريبتات `scripts/*-audit.js` بتنضّف وراها بالحذف) |
| `S3_BUCKET` | ملفات اختبار مع ملفات عملاء في نفس المكان |
| `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET` | **توكن اتولّد على staging شغّال على الإنتاج** |
| `TWILIO_*` | رسايل SMS اختبار بتروح لأرقام حقيقية وبتتحاسب |
| بوابة الدفع | معاملات اختبار على حساب حقيقي |

### ٣) لازم يبقى منفصل ومستقر

`SETTINGS_ENCRYPTION_KEY` و`PII_ENCRYPTION_KEY`: مستقلين عن الإنتاج، **وثابتين من أول يوم**.
تغييرهم بعد التشغيل بيبطّل فك كل القيم المحفوظة — والرقم القومي للفني بيتلف تفرّده كمان
(ADR-0045).

## اللي الفاحص **مش** بيغطّيه (بند نشر مش بند كود)

- **إصدار Postgres/Redis الفعلي** على السيرفرين — الفاحص بيقرا ملف env مش بيتصل بالخوادم.
  اتأكد يدويًا: `psql -c "select version()"` و`redis-cli INFO server`.
- **حجم البيانات**. staging بألف صف مش هتكشف استعلامًا بيموت على مليون. الحل المتاح:
  `scripts/migration-dry-run.sh` بيرجّع نسخة من الإنتاج ويقيس عليها (ج-١١).
- **موارد السيرفر** (RAM/CPU/قرص). staging أضعف بتكشف مشاكل الأداء بدري (كويس)؛ staging أقوى
  بتخفيها (خطر).

## قبل كل نشر

```bash
node scripts/env-parity-check.js --env <ملف البيئة> --as staging   # أو production
node scripts/check-migrations.js
node scripts/check-migration-safety.js
scripts/migration-dry-run.sh
```
