## 2. إيه اللي شغال فعلاً (مش خطة — كود مبني ومُختبر حي)

### 2.1 `apps/api` (NestJS + PostgreSQL/PostGIS + Redis + BullMQ)

**21 موديول، كل واحد فيهم شغال ومختبر حي على Postgres/Redis حقيقيين** (مش mocks — كل اختبار اتعمل بـ curl/Jest/Playwright/flutter test ضد سيرفر شغال فعلي، وأي بَقّة حقيقية اتلقطت اتوثّقت بصراحة في الـ README بتاع الموديول). الموديولات:

`admin` (RBAC هرمي، لوحة تحكم، dashboard analytics)، `audit` (سجل نشاط)، `auth` (OTP، JWT، refresh rotation)، `catalog` (فئات/خدمات/تسعير مناطق ومستويات/إضافات)، `chat` (شات الطلب + شات الدعم العام)، `customers`، `feature-flags`، `geo` (مدن/مناطق/نطاقات خدمة + رسم مضلّعات)، `matching` (توزيع الطلبات على الفنيين، BullMQ delayed jobs)، `notifications` (FCM/Twilio/SMTP dispatchers + توجيه حسب الدور)، `orders` (دورة حياة الطلب الكاملة + عروض الأسعار الوسيطة)، `payments` (Paymob + FawryPay + محفظة + صرف)، `payouts`، `pricing`، `promotions` (أكواد خصم + نقاط ولاء)، `ratings`، `settings` (محرك إعدادات ديناميكي)، `support` (شكاوى + تذاكر دعم)، `technicians` (اعتماد/مستويات/شركات وفرق/مناطق عمل)، `users`.

**التشغيل**: `cd apps/api && npm run start:dev` (يحتاج Postgres+Redis، `infra/docker/docker-compose.yml`). **قبل أي commit جديد**: `npx tsc --noEmit && npx nest build && npx jest` — الثلاثة لازم يعدّوا نضيف (كانوا نضيف آخر مرة اتشغّلوا، commit `770f1c6`).

### 2.2 `apps/admin` (Next.js 16 + shadcn/ui)

**كل الشاشات المخطط لها موجودة ومختبرة حي (Playwright ضد باك-إند حقيقي)**: نظرة عامة، موظفين، فنيين (+ مناطق عمل + مسار تحقق وسيط)، عملاء، طلبات (+ استرجاع + بنود عرض سعر + إعادة تعيين فني)، تقارير، شكاوى (+ تصنيف خطورة قابل للتعديل)، تذاكر دعم، **محادثات الدعم (جديد، آخر commit)**، طلبات صرف (+ تفاصيل بنود)، أكواد خصم (**+ تقييد بخدمات/مناطق، جديد**)، أسباب إلغاء، توجيه إشعارات، شركات/فرق فنيين، سياسة مستويات فنيين، كتالوج (+ تفاصيل خدمة كاملة)، مدن ومناطق (+ رسم مضلّعات تفاعلي بـ Leaflet)، إعدادات، Feature Flags (+ استهداف صريح)، سجل نشاط.

### 2.3 `apps/customer-app` و`apps/technician-app` (Flutter)

**كود شغال حقيقي، مش تطبيق فاضي** — auth بالـ OTP، تصفح كتالوج + إضافات اختيارية، إنشاء طلب، تتبع لحظي بخريطة Google Maps حقيقية، شات (نص + صور + **شات دعم عام، جديد**)، دفع (محفظة + بطاقة WebView + **فوري بكود مرجعي، جديد**)، تقييم، إلغاء بسبب+رسوم، عروض سعر وسيطة (موافقة/رفض)، **إشعارات push مُهيّأة (جديد، محتاجة مفاتيح Firebase حقيقية بس)**. الفني: نفس دورة الطلب كاملة، ملاحة خارجية، كشف أجهزة مكسورة (root/jailbreak).

**Flutter SDK**: `/opt/flutter/bin` (مش في PATH افتراضياً). اختبارات حية حقيقية في `test_live/` لكل تطبيق.

## 3. الشغل اللي اتعمل في الجلسة دي تحديداً (السياق المباشر قبل الإجازة)

بالترتيب الزمني، كل واحد منهم commit منفصل ومختبر حي بالكامل ومدفوع للفرع:

1. **`support_chat` (شات دعم عام)** — `GET /chat/support-thread` (عميل، get-or-create)، `GET /admin/support-chat-threads` (قايمة أدمن)، `resolveParticipant` اتوسّع يقبل أي أدمن عنده `support_tickets.manage` كطرف في أي خيط دعم عام. شاشتين جداد في `apps/admin` (`/support-chat`, `/support-chat/:id`)، `ChatScreen.support()` جديد في `apps/customer-app` + زرار دعم في الشاشة الرئيسية. اختبار حي كامل (curl + Playwright + `test_live/support_chat_live_test.dart`).
2. **تقييد أكواد الخصم بخدمات/مناطق** — الباك-إند كان جاهز بالكامل من زمان، بس مش معروض في فورم `/promotions`. أضيف قسمين checkbox، اتأكد حياً من الـ DB.
3. **تكامل عميل FCM** — `firebase_core`/`firebase_messaging` في التطبيقين، `PushNotificationService` جديد بيسجّل الجهاز بعد تسجيل الدخول (`POST /devices` الموجود من زمان). فشل صامت مقصود من غير ملفات Firebase حقيقية، بلجن Android شرطي عشان الـ build ميتكسرش. اتأكد حياً إن الـ try/catch شغال فعلاً (نداء مباشر لـ`registerCurrentDevice`، مش مجرد افتراض).
4. **نقاط ولاء قابلة للتعديل** — إعدادين جداد (`loyalty.earn_points_per_100_egp_spent`, `loyalty.point_value_cents`) في محرك `settings`، `LoyaltyService.earn()` بتقبل `EntityManager` اختياري دلوقتي عشان تشتغل جوّه نفس transaction التسوية. اتأكد حياً: طلب 300ج كسب 3 نقاط، بعد تغيير المعدل لـ3 من `/settings` طلب تاني كسب 9 — الإعداد ديناميكي فعلاً مش مجمّد.
5. **`ops_manager` بقى عنده صلاحية شات/تذاكر الدعم** — migration بس، مفيش تعديل كود (`support_tickets.manage` اتمنحت لدور إضافي). اتأكد حياً: مدير عمليات حقيقي شاف وقرا شات دعم بنجاح.
6. **`GET /admin/wallets/:userId`** — قراءة بس، أي أدمن. كارت "المحفظة" جديد في صفحتي `/customers/:userId` و`/technicians/:id`. اتأكد حياً بـ curl + Playwright (رصيد وحركات حقيقية ظهروا صح).
7. **شات داخلي (موديول `internal-chat` جديد بالكامل)** — جدول منفصل (`internal_chat_threads`/`internal_messages`)، أزواج مسموحة admin↔admin وadmin↔technician بس. صفحتين في `apps/admin` (`/internal-chat`)، شاشتين في `apps/technician-app` (زرار "تواصل مع الإدارة"). اتأكد حياً بالكامل (curl + `test_live/internal_chat_live_test.dart` + Playwright) — idempotent، رفض فني↔فني (400)، رفض عميل (403).

كل التفاصيل الكاملة لكل نقطة موجودة في الـ README بتاع الموديول المعني (`apps/api/src/modules/chat/README.md`, `apps/api/src/modules/promotions/README.md`, `apps/api/src/modules/payments/README.md`, `apps/api/src/modules/internal-chat/README.md`, `docs/03-external-integrations.md` §4.1) وفي `apps/admin/README.md`/`apps/customer-app/README.md`/`apps/technician-app/README.md`.

## 4. طلب المستخدم الأخير — **كله اتقفل وانفّذ بالكامل**

المستخدم طلب 4 حاجات في رسالة واحدة، بالإضافة لملف اللقطة ده نفسه. **الخمسة كلهم اتعملوا، اتختبروا حياً، اتوثّقوا، واتعمل commit+push ليهم**:

1. **✅ الملف ده نفسه** — اتكتب الأول قبل أي حاجة تانية (طلب صريح).
2. **✅ نقاط الولاء (loyalty) قابلة للتعديل من السيستم**: "الفلوس بتتحسب بكم نقطة؟ خليها flexible... حط الخانة في السوبر أدمن". إعدادين جداد في محرك الإعدادات (`settings` table، مُدار من `/settings` في `apps/admin`):
   - `loyalty.earn_points_per_100_egp_spent` = 1 (نقطة واحدة لكل 100 جنيه إنفاق)
   - `loyalty.point_value_cents` = 100 (كل نقطة = 1 جنيه لو اتصرفت)
   أرقام "متوسط صناعة" تجريبية زي ما طلب المستخدم بالظبط — **قابلة للتعديل فوراً من `/settings` من غير أي كود جديد**. `LoyaltyService.earn()` بتتنادى تلقائياً عند اكتمال أي طلب مدفوع (جوّه نفس transaction التسوية، عشان الذرّية). **اتأكد حياً**: طلب 300ج كسب 3 نقاط بالمعدل الافتراضي، وبعد تغيير المعدل لـ3 عبر لوحة الأدمن طلب تاني كسب 9 — إثبات إن الإعداد ديناميكي فعلاً.
3. **✅ توسيع صلاحية شات الدعم**: "عايز دايماً السيستم يوصل تحت الأدمن... المانيجر يعرف يكلم مع العميل". صلاحية `support_tickets.manage` (نفس الصلاحية اللي شات الدعم بيستخدمها) اتمنحت لدور `ops_manager` كمان (كانت بس `super_admin`+`support_agent`) — migration بس، مفيش تعديل كود. **اتأكد حياً**: مدير عمليات حقيقي (`+201000000002`) شاف قايمة شات الدعم وقدر يقرا/يرد.
4. **✅ الأدمن يشوف المحفظة**: `GET /admin/wallets/:userId` جديد (قراءة بس، مفتوح لأي أدمن)، معروضة في كارت جديد بصفحتي `/customers/:userId` و`/technicians/:id`. **اتأكد حياً**: محفظة عميل حقيقي فيها حركات قديمة (استرجاع/رسوم إلغاء/دفع) ظهرت صح بالمبلغ والاتجاه، وأدمن بدون صلاحية اترفض 403.
5. **✅ نظام تواصل داخلي (مدير↔فنيين، أدمن↔فنيين)**: موديول `internal-chat` جديد بالكامل، منفصل عن شات دعم العملاء — جدول منفصل (`internal_chat_threads`/`internal_messages`, مش لمسة على `chat_threads` الموجود). الأزواج المسموحة: أدمن↔أدمن، أدمن↔فني — **مش** فني↔فني (نطاق أول نسخة متعمّد). صفحتين في `apps/admin` (`/internal-chat`)، شاشتين في `apps/technician-app` (زرار "تواصل مع الإدارة"). **اتأكد حياً بالكامل**: فني بدأ محادثة مع أدمن، رسائل اتبادلت واتأكدت بالترتيب الصح، idempotent (نداء تاني رجّع نفس الخيط)، رفض فني↔فني (400)، رفض عميل (403)، رفض قراءة محادثة مش بتاعتك (403) — عبر curl + `test_live/internal_chat_live_test.dart` + Playwright على `apps/admin`.

**مفيش حاجة ناقصة من طلب المستخدم دلوقتي.** الخطوة الجاية (§6) هي استئناف "كمل بدون توقف" العام — الدَوَران على أي فجوة موثّقة تانية متبقية.

2. الفجوات المعروفة المتبقية وقت كتابة السطر ده (كلها قرارات عمل غير محسومة، مش أعطاب تقنية — راجع §8 لمبدأ "مفيش اختراع أرقام"):

   - `apps/api/src/modules/catalog/README.md`: مضاعف سعر مستوى الفني مش بيتطبّق تلقائياً وقت المطابقة (قرار عمل: هل العميل يوافق تاني على سعر جديد؟).
   - `apps/api/src/modules/promotions/README.md`: `POST /loyalty/redeem` بيخصم رصيد بس من غير أثر فعلي على سعر طلب (`loyalty.point_value_cents` الجديد جاهز يُستخدم لو القرار اتاخد).
3. لو مفيش فجوة موثّقة واضحة متبقية، ارجع لمبدأ "استخدم النظام فعلياً ولاقي الناقص" — شغّل السيناريوهات الحقيقية (طلب كامل، دفع، شكوى، صرف) وشوف هل في أي احتكاك أو نقص واضح.
4. زي دايماً: الفحوصات الثلاثة (`tsc`/`nest build`/`jest`) قبل أي commit في `apps/api`، `flutter analyze` قبل أي commit في التطبيقين، اختبار حي حقيقي (مش mocks)، توثيق صريح في الـ README المعني، commit+push، وحدّث الملف ده تاني في الآخر.

## 7. حاجات محتاجة منك (مفاتيح/قرارات خارجية) — ملخّص سريع

التفاصيل الكاملة بالخطوات في `docs/03-external-integrations.md`. باختصار شديد:

| الخدمة | المتغيرات | الحالة |

## 8. دروس/قرارات مهمة تستاهل تفتكرها

- **مبدأ حاكم في كل المشروع**: أي فشل في خدمة خارجية (Redis، queue، بوابة دفع، SMS) لازم يتلقّط ويتعامل معاه بأمان — أبداً ميكسرش أو يعلّق عملية حقيقية للمستخدم. الدرس اللي اتعلّمناه بالتجربة: `queue.add()` كانت بتعلّق طلب حقيقي دقايق وقت انقطاع Redis قبل ما نكتشف ونصلح.
- **بَقّة موثّقة معروفة، مش قابلة للإصلاح من كودنا**: BullMQ Worker مش بيرجع يعالج وظايف بعد انقطاع Redis طويل من غير إعادة تشغيل الـ process (مطابقة لـ GitHub issue #4479 في BullMQ نفسه). موثّقة في `technicians/README.md` و`ratings/README.md` و`matching/README.md`.
- **مفيش اختراع أرقام عمل (business numbers) من غير أساس**: أي رقم زي "معدل كسب نقاط الولاء" أو "خوارزمية ترقية فني تلقائية" اتأجّل لحد ما يتحدد رسمياً أو (زي نقاط الولاء دلوقتي) يتحط كإعداد قابل للتغيير بقيمة افتراضية معقولة بدل قيمة مُختلَقة ثابتة في الكود.
- **بيئة العمل دي (sandbox) محدودة**: مفيش جهاز/إيموليتور Android أو iOS حقيقي (كل اختبار UI بصري لتطبيقات Flutter بيتم عبر `flutter analyze` + منطق مُتحقق منه حياً بس مش رؤية بصرية فعلية)، والبروكسي بيمنع الوصول لدومينات مش على قايمة سماح (بوابات دفع حقيقية، خرائط تايلز، إلخ) — موثّق بالتفصيل في كل README متأثر.
- **اتفاقية الـ commits**: كل ميزة = commit منفصل، رسالة عربية موجزة، push فوري لـ`claude/home-services-app-plan-v13gb2`. الفحوصات الثلاثة (`tsc`/`nest build`/`jest`) لازم تعدّي قبل أي commit في `apps/api`. `flutter analyze` لازم يعدّي نضيف قبل أي commit في التطبيقين.
