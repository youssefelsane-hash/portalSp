# ADR-0056 — اعتماد تخصص المساعد وحدود المدينة

- **الحالة**: مقبول
- **التاريخ**: 2026-08-30
- **يلغي**: ADR-0054
- **يصحح جزئيًا**: ADR-0055
- **السياق**: تصحيح مباشر من المالك بعد تجربة النظام

## القرار

المساعد والفني شخصان مهنيان داخل نفس منظومة الحسابات، ويمكن للأدمن تحويل نوع الحساب بين
الدورين، لكن التحويل لا يلغي حدود الصنعة ولا ينشئ اعتمادًا وهميًا.

1. المساعد يقدّم على خدمة أو فئة، ويمر بموافقة الأدمن مثل الفني تمامًا.
2. لا يظهر الشخص لخدمة إلا إذا كان لديه اعتماد مباشر عليها أو اعتماد على فئتها، مع بقاء الحجب
   الإداري طبقة إضافية.
3. قوائم «إضافة فني» تعرض نوع `technician` فقط، وقوائم «ضم مساعد» تعرض نوع `assistant` فقط.
4. ضم المساعد، يدويًا أو تلقائيًا، يقتصر على مدينة الطلب. تعيين نطاق واحد داخل المدينة يسمح له
   بالظهور في باقي نطاقات المدينة، لكنه لا يسمح بالانتقال إلى مدينة أخرى.
5. بعد اجتياز حاجزي التخصص والمدينة، ترتيب المساعدين يكون بالمسافة أولًا، ثم المستوى والتقييم.
6. الحراسة تُعاد وقت القبول أو الحفظ داخل المعاملة؛ فلتر الواجهة وحده لا يكفي ولا يمكن تجاوزه
   باستدعاء API مباشر أو قبول عرض قديم بعد سحب الاعتماد.
7. مسارات الفني القائد وقواعد نطاقه الحالية لا تتغير بهذا القرار.

## سبب القرار

السباكة والكهرباء والمحارة مهن منفصلة، والمساعد المحترف داخل إحداها ليس مساعدًا صالحًا تلقائيًا
للأخرى. وفي الوقت نفسه، تقسيم المدينة إلى نطاقات داخلية لا يجب أن يخفي مساعدًا قريبًا داخل نفس
المدينة؛ المسافة هي ترتيب داخل المدينة، وليست تصريحًا لعبور المدن.

## التحقق

- اختبارات اعتماد الخدمة والفئة والحجب لكلا الدورين.
- اختبارات نفس المدينة عبر نطاقين، مدينة مختلفة، وتعطيل النطاق.
- اختبارات قوائم التجنيد والقبول المتزامن وإعادة فحص الأهلية وقت القبول.
- واجهة الأدمن تقرأ قائمة مساعدي الطلب المؤهلة من endpoint مخصص بدل قائمة الفنيين العامة.
